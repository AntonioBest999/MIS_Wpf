# МИС · облегчённая версия на WPF

Отдельный проект, который работает с **той же базой PostgreSQL**, что и WinForms-приложение `ЦРБ_и_все_все_все`.
Схему базы он не меняет и миграций не создаёт: классы модели (папка `Model`) скопированы из WinForms-проекта как есть.

## Запуск

1. Откройте `MisWpf.sln` в Visual Studio 2022 (нужен .NET 8).
2. В `appsettings.json` впишите пароль от PostgreSQL вместо `ВСТАВЬТЕ_ПАРОЛЬ` (строка та же, что в WinForms-проекте).
3. Запустите (F5). Вход — теми же логинами и паролями, что в основном приложении.

## Рабочие места

| Должность (Employee.Position) | Что открывается |
|---|---|
| ReceptionDoctor — врач приёмного | очередь по этапам, осмотр в 4 шага, назначения, решение; кнопка «Новое поступление» |
| ReceptionNurse — медсестра приёмного | оформление поступления и список поступивших за смену |
| LabTechnician — лаборант | очередь заказов, ввод результатов, завершение заказа |

## Что и куда сохраняется

| Действие | Таблицы |
|---|---|
| Новый пациент | `patients`, `PatientContact` |
| Поступление | `Admission` (статус «Поступил») |
| Анализы | `LabOrders` + `LabOrderItems` (показатели берутся из `LabParameters` по кодам) |
| Направление на ЭКГ / рентген / УЗИ / КТ | `Attachments` без файла, статус Draft. «Отметить выполненным» → Finalized + заключение в `InterpretationText` |
| Осмотр | `PrimaryInspections` + `GeneralData`, `SkinData`, `RespiratoryData`, `CardiologyData`, `AbdomenData`, `NeuroData`, `AnamnesisVitaeData` |
| Госпитализация | `Hospitalizations` (статус «Госпитализирован», номер «N:ГГГГ» как в WinForms), `Admission.Status` = «Направлен в отделение» |
| Отказ / перевод в другое ЛПУ | `Admission.Status` = «Отказ в госпитализации» / «Переведён в другое ЛПУ», `IsActive = false`; причина и рекомендации — в `PrimaryInspections.ProvidedCareByPO` |
| Результаты лаборанта | `LabOrderItems.Result/Comment/PerformedAt/PerformedById`, `LabOrders.Status` = Completed |

Совместимость с WinForms-версией:
* пациента, отправленного в отделение из WPF, заведующий видит в WinForms как обычно (статус госпитализации «Госпитализирован»);
* если заведующий отказал, WinForms ставит поступлению «В приёмном отделении», а госпитализации — «Отклонён заведующим»; WPF показывает такого пациента в группе «Возвращены заведующими» и при повторном направлении сохраняет тот же номер истории болезни;
* поступления, по которым осмотр уже сохранён в WinForms, в очередь WPF не попадают.

## Где что менять

* **Критерии осмотра** — `Exam/ExamDefinitions.cs`. Первый вариант в каждой строке считается нормой.
* **В какие поля БД пишется осмотр** — `Exam/ExamMapper.cs`.
* **Профили анализов** (какие показатели входят в «ОАК», «Биохимию» и т.д.) — `Services/OrderService.cs`.
* **Цвета и стили** — `Themes/Theme.xaml`; карточки очереди — `Views/CommonTemplates.xaml`.
* **Пороги таймера и частота обновления** — раздел `Reception` в `appsettings.json`.

## Чего пока нет в базе (предложения для миграций в WinForms-проекте)

Сейчас обходится без изменения схемы, но для полноценной работы стоит добавить:

1. `Admission.Number` — номер поступления (годовая нумерация); сейчас показывается Id как «П-123».
2. `Admission.IsUrgent` / приоритет — отметка «Срочно» на карточке.
3. `Admission.RefusalReason`, `Admission.Recommendations` — вместо записи в `ProvidedCareByPO`.
4. `Hospitalization.RejectReason` — причина отказа заведующего (сейчас WinForms её не сохраняет).
5. Отдельная таблица направлений на инструментальные исследования вместо записей `Attachments` без файла.
6. Поля для новых неврологических критериев (фотореакция, Ромберг, сила/тонус и т.д.) — сейчас они складываются фразами в `NeuroData.NeuroDesc` и `MentalDesc`.
